# 固定工作量下的吞吐与实际交错

首批已经量出取消后的等待，但改变块大小也改变了取消后继续做的工作量。第二批保持请求完整完成，隔离分块、在途窗口和调度策略的影响。模型的“固定工作”指相同输入和输出任务，不直接等于不同分块下 FLOPs 相同；Metal 则固定总递推次数。

## 问题与假设

| 实验 | 固定项 | 改变项 | 应观察的结果与反证 |
| --- | --- | --- | --- |
| 模型单请求吞吐 | 同一模型、A 的全部输入、最终首 token、求值策略 | A 的块大小 32／128／512 | 量出分块调用和物化的代价；小块不预设更好 |
| 模型请求交错 | A 和 B 全部输入及输出、参考结果、块大小 | serial／interleaved、受限／宽松配额 | 宽松配额只有在 B 真正被调度时才可能提前产生 token；若无剩余 A 块则应记录无交错机会 |
| Metal 固定工作吞吐 | 同一 kernel、同一 buffer、总块数、每块工作量 | 真正滚动的在途上限 1／2／4 | 测 CPU 往返与设备填充的影响；总提交量必须完全相同 |

模型吞吐是输入 prompt token 的处理速率，不是连续 decode 的输出 token/s。Metal 吞吐是该数值递推工作量的速率，不是模型吞吐。两者数值不横向比较。

## 模型对照

A 为 512 个合成 token，B 为固定 32 个 token。B 由控制线程在 A 第一块的求值调用窗口到达。计算仍由一个模型线程管理；interleaved 在已完成的块边界暂停 A、完整执行已准入的 B，再恢复 A。B 执行期间 A 的私有 KV 保留，共享模型 pool 不可重置。

serial 与 interleaved 都必须处理相同的 A/B 输入，不能通过取消 A 获得速度优势。受限配额让 B 等待 A 归还预留；宽松配额允许两个请求同时持有私有页槽。每层页 ID 不能相交，A 恢复后的结果必须匹配同块大小的隔离参考。

chunk 512 覆盖整个 A，是没有中间交错机会的对照。A 最终块完成后立即记录 A 结果，不能为了显示 B 先完成而延迟 A 的结果事件。控制线程晚到的样本保留，不重试到满足期望为止。

新增指标包括完整工作量的完成时间、prompt tokens/s、B 从到达到准入／实际计算／首 token 的分段时间、A 完成时间与峰值资源。指标逐 trial 重算，不相减两个不同分布的中位数来代替真实阶段耗时。

中间求值策略作为显式配置。主路径 `pools-only` 遵循 tiny-llm 的参考分块方式：中间块只物化 KV，最终块再求值输出 token。`token-and-pools` 保留首批每块额外求值 token head 的方式，作为求值策略对照。记录每块是否实际求值 head，不混合两种策略，也不把它们的差异都归因于调度。隔离数值参考使用同一分块和求值策略。

## Metal 对照

固定总块数，例如 16 块。每个 command 使用同一真实 buffer 上的递推状态，同一队列保证块间数据依赖。完成通知归还提交额度，主机才能提交下一块；记录每次提交和完成后的在途量，而非一次性提交 window 个命令就结束。

最后完成后验证全部输出，确认总提交数、总完成数、最终资源所有权和峰值在途数。计时覆盖首提交到最后完成观察；另列 GPU 原始起止和控制／回调间隔。

## 执行顺序

先各做一个小负载 smoke，独立检查事件和数值，再运行固定种子的配置顺序。新 GPU 测量串行。首批结果不覆盖、不混入新实验：第二批保存到 `results/batch2/`，同时固定源码、二进制和运行命令。

小批量用于确认策略与测量路径。通过后选择关键对照扩大重复次数，报告原始分布及不确定性；不因一次结果不理想而更换样本。下一步还包括错误路径、取消相位、持续 decode 干扰、必要清理依赖和相同策略下的 Swift 抽象比较。
