# P8 首个协议模型：取消、完成义务与资源转交

2026-10-29。状态：首个有限协议门槛已实现并[独立核验](../results/batch5/protocol-model-REPORT.md)：836状态/2704边、6最短反例及无服务保证lasso；v2补强状态断言，19项测试通过。独立issued-operation账本负责从历史检查义务未遗失；局部状态断言不能单独证明此点。它不替代Swift类型系统、完整成本定理或P0–P7未完成实验，不加载设备、不模拟硬件耗时，也不把探索状态数量解释为性能样本。

## 来自现有证据的最小构造

首批区分取消受理、资源归还与B结果；P3验证生产者依赖对实际priority传播的影响；P4证明局部scope不足以阻止跨scope别名，并验证owner/epoch；P6显示批量提交改变仍需完成的单位；P7显示共享引用与私有页有不同释放条件。首版只形式化**一个私有资源、A→B两代所有权**，共享引用与意图/工具效果留作独立扩展，不用私有资源结论冒充一般组合安全。

动作字母包括：`submit_A`、`cancel_requested/accepted`、`close_A`、`device_start/finish`、`host_observe`、`cleanup_start/finish`、`release_A`、`request/acquire/submit/result_B`、`drop_result`、`completion_unknown`。资源状态、设备访问状态和主机完成见证分别记录；`cancel_accepted`与`close_A`不是同一个动作。已接受取消后、关闭提交前的提交在模型内合法，关闭后提交才违反协议。

A最多提交两个设备操作，B提交一个。A的设备队列按顺序执行，CPU收尾只能在所有已提交访问的成功完成被观察后开始。owner持有完成义务，不依赖用户保留结果句柄；丢弃结果只改变结果需求。未知完成进入quarantine，不能凭timeout/错误或丢弃结果归还资源。模型不声称恢复未知设备错误。

## 独立检查的性质与反例

穷举合法动作交错，分别核对：

1. B取得同一资源之前，A所有设备访问都已结束，主机已观察完成，必要CPU读取已结束。
2. 关闭提交后没有新A提交；资源代次不能倒退、重复释放或允许旧代访问。
3. 丢弃结果/取消/未知完成不会消除已经建立的访问义务；quarantine状态不能伪造资源已归还或整个trial已drain。
4. 正常无错误路径存在完成执行；不把“存在可完成路径”当所有调度都会及时完成。

独立于转移生成器的状态断言检查上述条件。另逐项移除守卫（提前释放、关闭后继续提交、丢弃结果即释放、未知完成即释放、旧代许可仍可访问），搜索最短反例。反例只在逻辑模型内运行，绝不在GPU上制造数据竞争。每个mutant单独报告被破坏的性质，不以发生了任意错误就宣称目标反例成立。

安全性与进展分开：允许无关CPU工作持续占用服务时，可构造资源仍正确持有、B却永远未得到结果的合法循环。有限状态搜索不能枚举无限时间；输出由可达前缀与一个合法自环构成的证书，说明缺少服务假设时安全协议本身不产生响应时间界。

## 成本关系与明确假设

候选依赖图保留设备完成→主机观察→必要CPU清理→资源归还→B准入→B服务。取消受理是另一节点，不自动删除已经提交的节点；独立资源对照可以没有A归还→B准入这条边。

对一个有限无环的事件图，只有在每个节点的服务成本上界C(v)与依赖满足后的排队/调度上界S(v)都已给定时，才可递推条件性完成上界：

`E(v) ≤ max(E(u) for u in predecessors(v)) + S(v) + C(v)`。

CPU服务、设备队列/执行、完成通知和外部工具有各自的S/C假设。不能把CPU worker和GPU lane数量相加，也不能用本次样本最大值填入S/C便宣称最坏界。只有公平性而没有有界服务延迟，最多支持适当条件下的最终进展，不能推出墙钟上界。本模型不直接移植PriML定理；PriML的关联在于依赖和服务条件必须进入响应性论证。

首版输出有限状态安全检查、每个负例的最短动作轨迹、缺少服务假设的lasso证书，以及事件/状态定义。类型约束、共享资源、嵌套/取消权限、实际调度成本和完整PL子集仍是后续门槛。
