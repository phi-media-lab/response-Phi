# 假设与证据对应

## 首批实证

| 问题 | 应有的原始证据 | 独立检查 | 不能由此推断 |
| --- | --- | --- | --- |
| 取消反馈与实际停止是否分离 | requested、accepted、observed、stopped 的单调时间 | 重算两段延迟，核查取消触发相位 | ACK 等于 GPU 停止 |
| B 是否真正等待 A 的资源 | 配额、owner、release、admit、容量对照 | 受限容量顺序与账目；宽松容量移除准入依赖 | 单线程模型的提前 admission 等于提前执行 |
| 设备访问后才无条件转交 | 具体 buffer／页面身份、提交、完成观察、generation | 没有在途访问时才归还；不重复释放 | 全局 GPU 空闲或所有层自动正确 |
| 剩余在途工作是否影响重启 | 块大小、提交窗口、取消相位、剩余工作量、结果延迟 | 同一计算与输入下改变单一参数 | 小样本更快即最坏时间保证 |
| 清理是否成为关键依赖 | device end、CPU callback、cleanup、release、admit | 固定设备工作后比较 CPU 竞争与调度 | host task priority 改变 GPU 优先级 |
| 抽象是否有 PL 价值 | 固定策略的手工／封装实现、误用与组合案例 | 编译／运行拒绝、漏检与开销 | 仅缩短计算块就证明需改语言 |

## 首版实施边界

tiny-llm 实验复用真实参考模型与 paged KV，但控制器、配额与取消属于新增实验代码。保守同步基线可以测量取消发出至求值返回的延迟；它不自动提供请求级设备完成 token。

Swift Metal 探针使用真实 GPU buffer，但算子不构成完整模型。它可以验证物理 buffer 转交，首个结果不能命名为 TTFT。

资源池守恒与事件检查是观测到的执行路径证据。静态约束、模型检查和性能定理在后续阶段独立开展。性能失败、触发相位不符和数值错误必须留在原始记录中。

## 证据交付

每批保留环境快照、实际源文件哈希、精确命令、退出码、stdout／stderr、每次 trial 原始事件和聚合结果。既有 tiny-llm 工作区含本地修改，commit 之外的源码哈希是本次来源标识的一部分。

pilot 的用途是确认机制与测量路径；满足数值和协议约束后，再做足够重复的性能比较。若负结果指出最初解释不成立，更新假设和下一项实验，不删除该结果。
